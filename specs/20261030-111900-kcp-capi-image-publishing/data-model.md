# Data Model: KCP CAPI Image Publishing

**Feature**: `001-kcp-capi-image-publishing` | **Date**: 2026-10-30

## Entities

### Image

A publishable OCI artifact for one manager binary.

| Field | Type | Description | Required | Source |
|-------|------|-------------|----------|--------|
| `name` | string | Full registry path, e.g. `ghcr.io/jimmidyson/kcp-capi-core` | Yes | Fixed table in `scripts/image-tags.sh` + `.ko.yaml` mapping |
| `shortName` | string | Hyphen suffix, e.g. `core`, `nutanix-infrastructure` | Yes | Derived from `APIExport` / provider name; `kcp-capi-` prefix stripped locally |
| `importpath` | string | ko import path, e.g. `ko://github.com/jimmidyson/kcp-cluster-api/cmd/core-manager` | Yes | `.ko.yaml` `builds[].importpath`; ko image name mapping |
| `moduleDir` | string | Directory containing the module (`"."` or `"providers/nutanix-infrastructure"`) | Yes | Determines which `go.mod` to `go list -m` from |

**Validation**:
- `name` matches `^ghcr\.io/jimmidyson/kcp-capi-[a-z0-9-]+$`
- `moduleDir` exists and contains `go.mod` and `cmd/<name>/main.go` or equivalent
- Exactly 6 rows at v1 (root: 5 + 1 provider); future providers add one row each

### OCI Tag Set

The ordered set of tag strings pushed for one Image at one Release.

| Field | Type | Description | Required | Example |
|-------|------|-------------|----------|---------|
| `repoTag` | string | Repo version alias | Yes | `v0.2.0` |
| `longTag` | string | Human-readable provenance | Yes | `v0.2.0-capi-v1.15.0-kcp.13` (provider: `v0.2.0-capx-v1.11.0-kcp.3-capi-v1.15.0-kcp.13`) |
| `forkTag` | string | Upstream fork version alias | Yes | `v1.15.0-kcp.13` (Nutanix: `v1.11.0-kcp.3`) |
| `branchTag` | string | Floating main tag | On `main` pushes only | `main` |
| `shaTag` | string | Per-commit tag | On every push | `sha-a1b2c3d` (7-char short SHA) |

**Validation**:
- Every string matches OCI tag regex `^[a-zA-Z0-9_][a-zA-Z0-9._-]{0,127}$`
- No tag contains `+` (Go semver `+build` replaced with `-` for OCI)
- All tags in one set point to the same digest (verified by `image:verify`)
- `longTag` length < 100 (guards future unusually long provider fork tags; hard limit 128)

### OCI Labels

Metadata embedded in the image config.

| Key | Value source | Required on |
|-----|-------------|-------------|
| `org.opencontainers.image.version` | `REPO_VERSION` (`vX.Y.Z` or `main`) | All |
| `org.opencontainers.image.revision` | Full `GITHUB_SHA` or `git rev-parse HEAD` | All |
| `org.opencontainers.image.source` | `https://github.com/jimmidyson/kcp-cluster-api` | All |
| `io.kcp-capi.capi-version` | `go list -m sigs.k8s.io/cluster-api` → `.Version` | All |
| `io.kcp-capi.capi-base` | `DRIFT.md` `Base:` line (upstream commit) | All |
| `io.kcp-capi.k8s-version` | `go list -m k8s.io/api` → `.Version` | All |
| `io.kcp-capi.capx-version` | `go list -m github.com/nutanix-cloud-native/cluster-api-provider-nutanix` inside `providers/nutanix-infrastructure` | Nutanix image only |
| `io.kcp-capi.<provider>-version` | Provider-specific upstream version | Future provider images |

**Validation**:
- `io.kcp-capi.capi-version` from `go list -m` equals the `-capi-` segment of `longTag`
- `io.kcp-capi.k8s-version` equals `go list -m k8s.io/api` version (cross-check, tag doesn't encode it)
- Provider images carry exactly one extra `io.kcp-capi.*-version` beyond the root set

### Release

A synchronized publish of all Images at one git commit.

| Field | Type | Description |
|-------|------|-------------|
| `repoVersion` | string | The root tag `vX.Y.Z` (semver, `0.y.z` until 1.0) |
| `providerTags` | map[string]string | Per-provider Go tag at same commit, e.g. `{"nutanix-infrastructure": "v0.2.0"}` (always equal to `repoVersion` in lockstep) |
| `commit` | string | 40-char SHA the tags point at |
| `images` | `OCI Tag Set[]` | One set per Image, all sharing `commit` |
| `changelog` | string | Generated by release-please from Conventional Commits |

**Validation / Invariants**:
- `repoVersion` and every `providerTags[*]` are identical versions (lockstep; FR-006). The manifest enforces this: `release-please` creates both `vX.Y.Z` and `providers/<name>/vX.Y.Z` from the same PR merge.
- `go get github.com/jimmidyson/kcp-cluster-api@vX.Y.Z` and `.../providers/nutanix-infrastructure@vX.Y.Z` both resolve at `commit`; if either tag is missing, `image:verify` fails.
- `bootstrap-sha` in `release-please-config.json` remains `281e4e3…`; first tag `v0.1.0` remains fetchable.

| Field | Type | Description |
|-------|------|-------------|
| `dir` | string | `providers/<name>` |
| `modulePath` | string | `github.com/jimmidyson/kcp-cluster-api/providers/<name>` |
| `managerPkg` | string | Go entrypoint, e.g. `./cmd/nutanix-infrastructure-manager` |
| `driftRecord` | path | `providers/<name>/DRIFT.md` |
| `upstreamImport` | string | Go import path whose version encodes the upstream fork, e.g. `github.com/nutanix-cloud-native/cluster-api-provider-nutanix` |
| `upstreamFork` | URL | Git URL of the fork, e.g. `https://github.com/jimmidyson/cluster-api-provider-nutanix` (for `task drift`) |

**Validation**:
- `modulePath` matches `dir` as Go requires (`kcp-cluster-api/` + `providers/<name>`)
- `go.mod` contains `replace github.com/jimmidyson/kcp-cluster-api => ../..` and restates all CAPI fork `replace`s
- `cmd/<name>-manager/main.go` imports `github.com/nutanix-cloud-native/cluster-api-provider-nutanix/controllers` (or equivalent)
- `go.mod`, `DRIFT.md` all present; each manager's `ko` importpath is listed in `.ko.yaml` (or the provider's own `.ko.yaml` if isolation needed)
## Relationships

```
Release  ──1:N──►  Image  ──1:1──►  OCI Tag Set (per release)
                        └─1:1──►  OCI Labels (embedded in manifest)
                ▲
                │
         Provider Module ──1:N──► Image  (one manager per provider, today 1:1)
                │
                └─────────►  Drift Record (one per provider fork)
```

- One `Release` publishes all `Image`s.
- Each `Image` belongs to at most one `Provider Module`; root images belong to none.
- Each `Provider Module` has exactly one `upstreamImport` whose `go list -m` version is the image's `forkTag`.

## State Transitions

None — this feature is build/release infra with no runtime state machine. The only transition is the release lifecycle:
`main commit` → `release-please PR` → `merge` → `tag push (vX.Y.Z + providers/*/vX.Y.Z)` → `publish-images.yaml` → `GHCR (3 aliases per image)`.
